# 在途 CRM 手机端可评审原型

直接打开 `index.html`。原型不依赖服务端、构建工具或网络资源。

可选验证：运行 `node --test prototype.test.mjs` 检查评审壳、页面数量与关键交互合同。

## 评审结构

- 左侧：14 个界面入口与已评审进度。
- 中间：可切换 375 × 667、390 × 844、430 × 932 的手机原型。
- 右侧：当前界面的评审目标、PRD 对照、关键边界、视觉参考和独立修改意见。
- 修改意见与“已评审”状态保存在浏览器 `localStorage`，可导出为 JSON。

## 页面清单

1. 工作台（快捷新增、今日日程、待处理、最近跟进记录）
2. 客户列表
3. 重复客户提醒（仅后台查重命中时出现）
4. 新增 / 编辑客户
5. 客户详情（概览、联系人、沟通记录）
6. 手工新增沟通
7. 跟进记录（周、月、列表视图，叠加查看日程与沟通记录）
8. 沟通记录详情
9. AI 材料输入
10. AI 处理、失败恢复与客户匹配
11. AI 未确认草稿审核
12. 补充沟通记录（补录遗漏信息并生成新版本）
13. 归档数据管理
14. 我的

## 建议走查路径

- 客户主路径：客户列表 → 新增客户表单 → 后台查重；无重复直接进入详情，发现候选才显示重复客户提醒。
- 手工沟通：工作台“新增跟进记录”或客户详情“新增沟通” → 保存正式记录 → 沟通详情 → 跟进记录。
- AI 沟通：工作台“待处理”中的 AI 草稿 → 未确认草稿 → 确认正式记录 → 沟通详情；确认前不会进入跟进记录。
- 跟进查看：底部“跟进记录” → 先看日期范围与类型筛选 → 使用日期导航和周、月、列表切换；列表默认覆盖全部时间，需要时从“筛选”选择业务线和时间。日程展示客户、可多选业务线及微信/手机/线下拜访渠道，不展示地址。
- 补充记录：沟通详情 → 补录上次遗漏的正文、结论、参与人或附件 → 保存为下一版本。
- 归档治理：普通销售端不展示管理入口；评审时从左侧页面目录以管理员身份查看归档与恢复流程。

## 边界

原型只覆盖 CRM 一期客户事实、沟通事实、AI 草稿确认与治理。三类对象严格分流：沟通记录是已发生事实，日程是有明确日期时间的计划，待处理是独立任务。待处理和未确认草稿只在工作台（以及“我的”草稿入口）展示，不进入跟进记录的周、月、列表视图或客户正式沟通时间线。界面不包含销售额、漏斗、客户评分/等级/价值、风险、赢单概率或 AI 销售建议。
